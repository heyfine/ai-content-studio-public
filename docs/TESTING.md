## 如何运行测试

```bash
pnpm test             # 跑全部测试
pnpm test -- --watch  # 监听模式
pnpm test <文件名>    # 只跑某个文件
```

## 覆盖率要求

- 核心逻辑（数据层 / 工具函数 / API）覆盖率目标：{{例如 80%+}}
- 跑覆盖率：`pnpm test -- --coverage`
- 覆盖率不足时，至少保证关键路径有测试

## 测试类型

| 类型 | 说明 | 位置 |
| --- | --- | --- |
| 单元测试 | 函数 / 组件 / 工具 | `{{tests/unit}}` 或 `{{src/**/*.test.ts}}` |
| 集成测试 | API / 数据层 | `{{tests/integration}}` |
| E2E | 用户主流程 | `{{tests/e2e}}` |

## 写测试的约定

- 组件测试：用 `@testing-library/react`，优先测行为（点击、输入、结果）而非实现细节
- 数据层/API 测试：避免打真实外部服务，用 mock（`vi.mock` / MSW）
- 修 bug 必加回归测试：先写能稳定复现 bug 的用例，修复后用例通过
- 测试文件与被测代码放一起（`xxx.test.ts`）或统一 `tests/` 目录，保持一致
